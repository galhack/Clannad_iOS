# iPad 性能与功耗验证

## 2026-10-23 / 0.1.5（6）

### 已确认的无效工作

Apple 播放器原来不设置 CADisplayLink 的刷新上限。iPad Pro M5 的实测静止对白
仍以 120 Hz 调用 SiglusHost.step；该方法每次都轮询脚本、执行整帧元素更新、
重新生成画面并调用渲染器。即使没有视觉变化，也会持续使用 CPU 和 GPU。
原生选择快照还会在每个回调里重复生成 JSON、分配缓冲区和解码。

### 本版实现

- 常规游戏回调上限 30 Hz；系统热状态 serious 或低电量模式为 20 Hz，critical 为 15 Hz。
  系统通知更新帧率，UIKit 属性仅在主线程设置。保留原来的 drawable 分辨率与文字质量。
- Host 复用运行时的动态内容判断：有输入或尺寸变化、脚本待继续、帧等待、文字展开、
  动画、转场或影片时继续整帧处理。静止等待时保留已有画面，不重新生成或提交整帧。
- 补足自动播放、立即播放和快进的唤醒条件；启动警告的主机帧等待也继续轮询。
- 静止期间仍维护音频工作线程、延迟播放、PCM/BGM 淡入淡出及语音音量路由。
  语音播放由音频系统继续驱动，不依赖持续 GPU 绘制。
- 从静止或后台恢复时重置元素帧时钟并请求新帧，避免新动画吃掉读者停留时间。
- 用完成帧计数决定是否更新原生 UI；无变化时不再反复解码选项。快进状态每 0.25 秒
  按时间查询，避免帧率降低后按钮更新变慢。

### 测量口径

基线为 7e8c3b2 / 0.1.4（5）的原始引擎与帧循环，仅加相同的性能日志；优化版为
0.1.5（6）。均在同一台 iPad Pro 13-inch（M5）读取 No.009 存档，在
seen0419 第 249 行“就要下雨了。”保持静止。未覆盖或删除已有存档。

显式设置 CLANNAD_PERF_LOG=1 才记录性能，每 5 秒输出一次。CPU 百分比使用
getrusage 的进程 user + system CPU 时间除以墙钟时间，100% 表示占满一个 CPU 核，
不是整颗芯片的百分比。engine_frames_s 是完成整帧更新的次数；静止跳过时为 0，
存在 FRAME 抑制绘制时不等同于实际呈现次数。基线每次回调都会处理整帧。
测试同时开启相同的 5 秒只读状态追踪和调试输入控制。

只比较无输入、无暂停、无加载的完整连续样本；调试命令复制时会短暂挂起进程，
其相邻样本不计入对比。截图和原始日志保留在被忽略的 build/ 下。

该场景的进程负载，不能直接换算为整机瓦数、温度下降或续航增幅。
